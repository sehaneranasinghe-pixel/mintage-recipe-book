PERMISSION MODEL – READ THIS ---------------------------- Every authenticated account can READ, ADD, EDIT and DELETE documents in the shared /recipes collection. This matches the requested shared staff workflow, but it means any registered user can change or delete any shared recipe. Favorites are stored under /users/{uid}/favorites and are per-user. Profile records are under /users/{uid}. Passwords are managed only by Firebase Auth; this app never writes passwords to Firestore. The rules intentionally do not restrict all recipe keys, to avoid rejecting legacy recipe documents with fields not represented in the upgraded editor. They validate core fields on writes. Review rules against actual production records and Firebase Emulator before publishing. Firestore rules are not a replacement for regular backups. FEATURES IMPLEMENTED IN THIS PACKAGE ------------------------------------ - Existing Firebase project/config and /recipes collection retained. - Email/password login, registration, password reset, logout confirmation. - Three UI languages: English, Sinhala and Tamil; saved in local storage and user profile when saved. - Shared recipe create/edit/delete; ingredients, quantity, unit, category, notes, created/updated timestamps and actor labels. - Built-in categories plus custom category entry. - Live case-insensitive search across recipe name, ingredient, quantity, unit, notes and category; category filter. - Per-user favorites. - Dashboard counts and recent recipe lists. - Profile nickname, language and password change (Firebase reauthentication may be required by Firebase for older sessions; the app reports errors). - JSON export and safe restore: existing document IDs are skipped; no existing document is overwritten. Restore requires a backup JSON file. - PDF selectable-text extraction using PDF.js loaded from a CDN. Pages with no selectable text are flagged as likely scanned. Review text is editable; an operator can approve a page-text record after manually confirming it. - Installable PWA shell and best-effort Firestore persistence. - Append-only recipe activity log when Firestore rules allow it. INCOMPLETE / NOT CLAIMED AS WORKING ----------------------------------- - OCR for scanned PDF pages is NOT implemented. The app detects pages with little/no selectable text and flags them; it does not recognize page images. - Automatic recipe boundary detection, ingredient/quantity/unit extraction, and duplicate matching are NOT implemented. The PDF review tool deliberately preserves extracted page text and asks a human to confirm details. It does not invent ingredients or quantities. PDF.js and its worker are loaded from cdnjs, so PDF extraction needs network access and CDN availability. - There is no backend/Cloud Function in this ZIP. A secure OCR pipeline would normally upload a PDF to private Cloud Storage, enqueue a Cloud Function, process pages using a managed OCR service, store extraction candidates with page references/confidence, and require a human approval step before any Firestore write. Cloud Vision / Document AI usage can incur charges; storage, function invocations, network egress and OCR pages may also be billable. Restrict uploads, enforce file-size/page limits, use IAM/service identities, avoid public buckets, and never expose service-account keys in browser code. - Account deletion is intentionally not implemented. Secure deletion requires recent authentication and a trusted backend; deleting an Auth user must not delete shared recipes. - No full historical recipe-version recovery. Activity entries are event logs, not restorable snapshots. Existing recipe edits are not version archived. - No automated browser-to-Firebase integration test was possible in this package build. Firestore sync, auth, PWA installation and offline writes must be tested in the actual Firebase project and target browsers. - Offline support is best effort only: service worker caches the app shell; Firestore persistence depends on browser support/storage policy. Do not treat offline writes as guaranteed until tested on the target devices. - Fonts are loaded from Google Fonts with system fallbacks; fonts are not bundled locally in assets/fonts. If the repository uses a project path, the relative asset paths in this package are designed for that deployment. A first visit needs network access to load Firebase SDKs and Google Fonts.
